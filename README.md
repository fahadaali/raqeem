# منصة رقيم
### منصة الإدارة المتكاملة (ERP) لمجمعات تحفيظ القرآن الكريم

بنية متعددة المستأجرين **جاهزة للتحول إلى SaaS** · واجهات عربية بالكامل (RTL) · تقويم مزدوج (هجري/ميلادي)
<br>تعمل كتطبيق مثبّت على الآيفون والأندرويد مع نظام إشعارات متكامل
<br>**شيفرة واحدة تعمل على خادم ذاتي (Node) وعلى Cloudflare (Workers + D1 + R2)**
<br>مرحلة أولى أحادية المستأجر · وطبقة SaaS كاملة جاهزة للتفعيل بمفتاح واحد

</div>

## نظرة عامة

منصة رقيم تطبيق ويب متكامل لإدارة مجمّع تعليمي قرآني بجميع فروعه ولجانه: المهام، الحضور الذكي،
الدورة المالية والاعتمادات، التقييم والنماذج، التقارير الرسمية، وسجل تدقيق غير قابل للتلاعب.

بُنيت المنصة منذ اليوم الأول كنظام **متعدد المستأجرين (Multi-Tenant)** يُشغَّل حالياً بواجهات
أحادية المستأجر — تفادياً للدين التقني عند التحول إلى منتج SaaS في المرحلة الثانية.

## التشغيل السريع

### أ) تشغيل ذاتي (Node)

```bash
npm install          # تثبيت الاعتماديات
npm run setup        # إنشاء القاعدة + البيانات التجريبية + الأيقونات
npm run gen:vapid    # توليد مفاتيح إشعارات الدفع (Web Push)
npm start            # تشغيل الخادم على http://localhost:3000
```

> المتطلبات: Node.js 20 فأحدث. لا تحتاج قاعدة بيانات خارجية — تعمل على SQLite افتراضياً.

### ب) على Cloudflare (كل المزوّدات من كلاود فلير)

```bash
npx wrangler login     # أو:  export CLOUDFLARE_API_TOKEN=…
npm run cf:link        # يتولّى السلسلة كاملةً
```

`cf:link` ينشئ قاعدة D1 ودلو R2، ويكتب معرّف القاعدة في `wrangler.toml` تلقائياً،
ويولّد الأسرار ويرفعها، ويطبّق المخطط، وينشر العامل، ويضبط `APP_URL` على رابطه،
ثم يهيّئ الجهة رقم ١ ويفحص صحة الخدمة. وهو صالح لإعادة التشغيل: يكتشف ما أُنشئ
سابقاً فلا يكرّره. جرّبه أولاً بـ `npm run cf:link -- --dry`.

الخطوات اليدوية المفصّلة والتشخيص: **[docs/CLOUDFLARE.md](docs/CLOUDFLARE.md)**

## الأساس المعماري (المقدمة الاستراتيجية)

| المتطلب | التنفيذ |
|---|---|
| **العزل المنطقي للبيانات** | عمود `tenant_id` إلزامي على كل جدول رئيسي (٤٣ جدولاً) |
| **فلترة الاستعلامات الشاملة** | طبقة `core/scope.js` تفلتر كل استعلام بـ `tenant_id` ثم `branch_id` آلياً |
| **تهيئة بيئة التشغيل الأولى** | المجمّع الحالي مُدخل كـ «المستأجر رقم ١» وجميع العمليات داخل نطاقه المعزول |
| **التخصيص الديناميكي** | الاسم والشعار والألوان تُقرأ من سجل الجهة لا من الكود (`White-labeling Basics`) |
| **مركزية التحديثات** | مصدر برمجي واحد لجميع الجهات — ولبيئتَي التشغيل معاً (نواة مشتركة + محوّلان) |
| **التخزين السحابي المعزول** | كل ملف تحت `tenants/{tenant_id}/...` — القرص المحلي أو **Cloudflare R2** بالواجهة نفسها |

### المرحلة الثانية — ما أجّلته الوثيقة، وقد بُني الآن

الوثيقة أجّلت أربعة بنود عمداً إلى المرحلة الثانية، وهي مبنيّة ومُدقَّقة الآن:

| البند المؤجَّل | ما بُني |
|---|---|
| **التسجيل الآلي** (Onboarding) | صفحة `/signup` تجهّز جهة كاملة — أدوار وصلاحيات وفرع وفصل وحساب مدير واشتراك — في عملية واحدة، مع فحص فوري لتوفر الرمز والبريد، وخيار المراجعة اليدوية |
| **خطط الأسعار** (Pricing Plans) | جدول خطط قابل للتحرير + صفحة أسعار عامة، وحدود (فروع/مستخدمون/تخزين) تُطبَّق فعلياً قبل الكتابة مع دعوة للترقية |
| **نظام الفوترة** (Billing System) | اشتراكات وفواتير بضريبة القيمة المضافة وأرقام متسلسلة وطباعة رسمية، ودورة يومية للتجربة والتجديد والتذكير، وسداد بالتحويل البنكي باعتماد المالك |
| **لوحة إدارة المنصة** (SaaS Owner) | لوحة مستقلّة على `/admin` بخمس عشرة شاشة، هي الطبقة الوحيدة التي تتجاوز عزل الجهات — ولذلك كل عملية فيها في سجل مقفل مستقل |

وبُني فوق هذه الأربعة **أربعة مستويات** تجعل اللوحة أداة تشغيل لا شاشة عرض:

| المستوى | ما يضيفه |
|---|---|
| **١ — إنفاذ ما وُعِد به** | مزايا الخطط تُحجب فعلياً برسالة ترقية صريحة · لقطات مؤشرات تاريخية بمنحنى نمو · سجل تشغيل الوظائف الدورية وصحتها · احتساب التناسب عند تغيير الخطة من **المدفوع فعلاً** |
| **٢ — النمو وإدارة العلاقة** | تقييم صحة كل جهة من ١٠٠ وتصنيف خطورتها · رصد فرص الترقية وقيمتها · بثّ إعلانات موجّهة تصل إشعاراً وشريطاً · صندوق دعم موحّد للتذاكر المُصعّدة · ملاحظات الجهة ومتابعتها التجارية |
| **٣ — الامتثال والأمن** | فاتورة إلكترونية بمعيار ZATCA (رمز QR بترميز TLV + مستند UBL 2.1 + سلسلة تجزئة) · تحقّق بخطوتين (TOTP) برموز استرداد · مراقبة محاولات الدخول · تصدير كامل لبيانات جهة دون تسريب غيرها |
| **٤ — عمق الفوترة** | كوبونات خصم تسري على التجديدات · إشعارات دائنة · بوابات دفع سعودية · تجاوزات حدود ومزايا لكل جهة · بيانات المشتري ورقم أمر الشراء على الفاتورة ومستند UBL |

الطبقة **تُشحن معطّلة**، فتعمل المنصة بواجهات أحادية المستأجر كما تشترط المرحلة الأولى،
ويفتحها الادمن بمفتاح واحد. التفاصيل الكاملة في **[docs/SAAS.md](docs/SAAS.md)**.

### الشاشة الرئيسية العامة

الزائر على `/` يرى صفحةً تعريفية **يحرّرها الادمن من لوحته** — واجهة أولى ومزايا وأرقام وأقسام
وتذييل — **وتُشحن منشورة بمحتوى افتراضي**: صفحةٌ رئيسية تُشحن مطفأة تعني أن الزائر يرى الدخول حتى ينتبه
أحدٌ لمفتاحٍ لا يعرف مكانه. ومفتاح النشر باقٍ لمن أراد إطفاءها — وحينها يعود `/` إلى شاشة الدخول.
والجذر للصفحة الرئيسية، وكل ما عداه امتداد: `/login` للدخول و`/dashboard` للوحة المجمّع.

| المسار | ماذا |
|---|---|
| `/` | **الصفحة الرئيسية** — للزائر وللمسجَّل معاً (وللمسجَّل زرُّ «لوحتي») |
| `/login` | شاشة الدخول الموحّدة — حساب المجمّع يُفتح على لوحته وحساب إدارة المنصة على لوحة المنصة، والخادم وحده يحسم النوع |
| `/dashboard` | لوحة تحكّم المجمّع |
| `/admin` | لوحة إدارة المنصة |

وهي الكتلة الوحيدة التي يكتبها الادمن ويقرؤها من لا حساب له، فتمرّ على مطهِّر **قبل الحفظ**:
`javascript:` و`data:` تُجرَّد من الروابط، والأطوال والأعداد محدودة، والصفحة تُبنى بـ `textContent`
لا `innerHTML`. والتطبيق المثبَّت يقلع على `/dashboard` مباشرةً: من ثبّته قصد العمل لا القراءة عن المنصة.

**المزايا مصنَّفةٌ في عائلات.** كل ميزةٍ تحمل اسم عائلتها نصّاً (`group`)، والصفحة تفتح عائلةً
كلّما تغيّر الاسم — فالترتيب هو التصنيف، ونقلُ ميزةٍ بين عائلتين تحريرُ حقلٍ واحد في اللوحة لا نقلٌ
بين قائمتين. والمشحون افتراضاً سبعُ عائلات تعدّ ما في المنصة كلَّه: العمل التشغيلي · الحضور والموارد
البشرية · المال والاعتمادات · القياس والتقارير · الحوكمة والامتثال · التواصل والإشعارات · المنصّة
والتشغيل.

**واللقطات تُولَّد لا تُلتقط باليد.** `npm run gen:screens` يفتح المنصّة في متصفّحٍ آلي على بيانات
التجربة ويصوّر ثماني شاشات في الوضعين الفاتح والداكن، بثلاثة عروضٍ لكلٍّ منها (٩٦٠ · ١٤٤٠ · ٢١٦٠)
تُبنى منها `srcset` — فالجوّال ينزّل ما يناسبه لا ما يناسب الشاشة الكبيرة. وتُعرَض في لوحةٍ مائلةٍ
في منظور، بظلٍّ ثلاثيّ الطبقات يُقرأ ارتفاعاً؛ وتُسطَّح اللوحة على الشاشة الضيّقة وعند طلب
`prefers-reduced-motion` يسكن طفوها.

### قوالب الفصول الدراسية

كان الفصل الافتراضي مكتوباً في الشيفرة — فصل واحد مدّته ١٥٠ يوماً لا يُضبط من أي واجهة. الآن
يُعرَّف من `/admin/terms` بتواريخ **نسبية** (شهر/يوم البداية + المدّة) فيصلح القالب لكل سنة دون
تحرير، ويُنسخ إلى كل مجمّع جديد **سنةً دراسية متّسقة**: الفصل الذي يقع فيه اليوم محورٌ تُبنى
السلسلة حوله، فتخرج مرتّبةً بفصل جارٍ واحد. ويمكن **فرض** قالب على المجمّعات القائمة: يُضاف حيث
لا يوجد رمزه، ويُتخطّى الموجود بلا مساس، ولا يُنصَّب جارياً — والنتيجة تقرير بمن أُضيف له ومن
تُخطّي ولماذا. والجدول الفارغ يرجع للسلوك القديم فلا ينكسر إنشاء المجمّعات.

### لوحة إدارة المنصة منفصلة عن المنصة

اللوحة على امتداد خاص بها (`/admin`) بهيكل واجهة لا يشترك مع هيكل المجمّعات في قائمة ولا شريط
علوي، وحساباتها في جدول `platform_admins` **لا عمود جهة فيه أصلاً** — فاستحالة ظهور الادمن داخل
مجمّع بنيويّة لا اتفاقية. ورمز كل طبقة يحمل جمهوره: رمز المجمّع `{sub, tid, role}` ورمز الادمن
`{sub, adm:1}`، وكل حارس يرفض رمز الآخر صراحةً. ولأن مفتاحَي التخزين مستقلّان تتعايش الجلستان
في المتصفّح نفسه: يبقى مدير المجمّع داخلاً في تبويب والادمن في آخر.

## تغطية بنود وثيقة المتطلبات (PRD)

<details open>
<summary><b>١. النظرة العامة والصلاحيات</b></summary>

- شاشة دخول موحّدة (SSO) تتعرف على الدور وتوجّه لوحة التحكم المناسبة
- واجهة مرنة: القوائم والأزرار تتغير بحسب صلاحيات المستخدم
- نظام `RBAC` صارم: ١٠ أدوار جاهزة × ٥٨ صلاحية قابلة للتعديل من الواجهة
- جلسات آمنة بـ `JWT` + رموز تحديث قابلة للإبطال + إدارة الأجهزة النشطة
</details>

<details open>
<summary><b>٢. الهيكلة المعمارية ونظام الفروع</b></summary>

- **مبدّل الفروع** في الشريط العلوي — تتحدث البيانات فوراً دون إعادة تحميل
- لوحة تحكم مجمّعة تقارن أداء الفروع للقيادة العليا
- فلترة مزدوجة على الخادم: عزل المجمّع أولاً ثم عزل الفرع
- **جدول التقاطعات** `user_branches` يربط المستخدم بالفروع المصرّح له بها
</details>

<details open>
<summary><b>٣. إدارة الفصول الدراسية والفترات</b></summary>

- **معالج إغلاق الفصل** بخمس خطوات: الموظفون المستمرون ← المهام المُرحّلة ← اللجان ← العهد والميزانيات ← الفصل الجديد
- **وسم الأرشفة**: شريط تحذيري ملوّن عند استعراض فصل مؤرشف
- عمود `term_id` محوري في كل الجداول (مهام، فواتير، حضور)
- **التجميد (Immutability)**: مُشغّلات على مستوى قاعدة البيانات تمنع أي تعديل أو حذف لسجلات فصل مغلق — لا يمكن تجاوزها حتى من داخل التطبيق
- **الترحيل الآلي**: سكربتات خلفية تنسخ السجلات المحددة إلى الفصل الجديد
</details>

<details open>
<summary><b>٤. إدارة اللجان والمهام</b></summary>

- ثلاث طرق عرض: **جدول إكسل** · **مخطط جانت** تفاعلي بالاعتماديات · **لوحة كانبان** بالسحب والإفلات
- **الجدول يُحرَّر في مكانه**: كل عمود حقلٌ يُضغَط فيُفتَح — الحالة والأولوية واللجنة والمكلّف والتواريخ والإنجاز والوزن. بلا نافذة تُفتح ولا صفحة تُعاد، وعمود المهمة مثبَّت فلا يضيع الصفّ عند التمرير
- **قوائم الأشخاص فيها بحث** في كل موضع يُسنَد فيه شخص — مهمةً كان أو تذكرةً أو عضوية لجنة أو تصفية تقرير
- **المهمة تحت لجنة لا تُسنَد إلا إلى أعضائها** — والمنسوب قد يكون في لجنة وأكثر، فيظهر في كلٍّ منها
- **مكتبة القوالب**: نافذة اختيار قوالب جاهزة مع تعديلها وتوزيعها قبل الاعتماد
- **محرك القوالب** يستنسخ القالب إلى مهام فعلية بتواريخ محسوبة في الفصل الحالي
</details>

<details open>
<summary><b>٥. الموارد البشرية والحضور</b></summary>

- **زر التحضير الذكي**: دائرة كبيرة تتغير (أخضر للحضور / أحمر للانصراف) مع خريطة تفاعلية توضح موقعك من الفرع
- **التتبع الجغرافي**: معادلة `Haversine` ترفض التسجيل خارج نطاق الفرع (٥٠ متراً افتراضياً، قابل للضبط لكل فرع)
- **التحضير من أكثر من فرع**: من عُيّن على فروعٍ عدّة تُقاس فروعه كلُّها ويُقبل أقربُها، والخريطة تتبعه
- **العمل عن بُعد**: علَمٌ في ملف الموظف يرفع اشتراط النطاق فيحضر من أي مكان، ويُعلَّم سجلُّه بذلك
- **ملف الموظف الشامل**: العقد، الحضور، الغياب، الإجازات، السلف، ومسير الرواتب — ويُحرَّر من مكانه
- **وثائق الموظف**: الهوية والإقامة والعقد والشهادات بتسميةٍ يكتبها المستخدم وتاريخ انتهاءٍ اختياري
- **أوقات الدوام من لوحة واحدة** — أيام العمل وساعاته على ثلاث طبقاتٍ يرث بعضها بعضاً:
  **المجمّع ← الفرع ← الموظف**. تُضبط للمجمّع كلّه، أو لفرعٍ بعينه، أو لكل منسوبٍ على
  حدة (المتعاون، والمعلّم المسائي، ومن دوامه يومان). وكلُّ صفٍّ يقول من أين جاء جدولُه:
  «موروث» أو «خاصّ». وزرُّ توحيدٍ يُعيد الفروع كلَّها إلى دوام المجمّع دفعةً واحدة
- **محرك الرواتب مبنيٌّ على هذه الجداول**: أيام العمل المتوقّعة من جدول كلِّ موظف لا من
  شهرٍ نمطيّ، والتأخّر يُقاس بدقائقه من بداية دوامه هو مع سماحه هو، والإجازة المعتمدة
  تُسقط يومها من الغياب، والخصومات لا تتجاوز المستحقّ فلا يخرج راتبٌ سالب
</details>

<details open>
<summary><b>٦. النظام المالي ودورة الاعتمادات</b></summary>

- **شجرة الاعتمادات**: واجهة مرئية لترتيب مراحل الاعتماد لكل نوع مستند
- **محرك حالة الطلبات**: `pending → approved_supervisor → approved_finance` — لا يمكن تجاوز خطوة إلا من صاحب الصلاحية (يُرفض بـ 403)
- مسار مرئي يوضح موقع الطلب في الدورة ومن اعتمده ومتى
- **الميزانية على مستويين**: الفرع **واللجنة** — فلكل لجنة بندُها وحسابها، ولا يذوب صرفها في وعاء الفرع. ويُخصم البند آلياً عند الاعتماد النهائي، ولا يُخفَّض معتمدُه دون منصرفه، ولا يُحذف بندٌ صُرف منه
- **مرفقات الفواتير**: سحب وإفلات مع قارئ يعاين الفاتورة داخل النظام دون تحميلها
- تخزين الملفات في مسار معزول بمعرّف الجهة مع رابط في قاعدة البيانات
</details>

<details open>
<summary><b>٧. نظام التقييم وبناء النماذج</b></summary>

- **منشئ النماذج المرئي**: سحب وإفلات لتسعة أنواع حقول دون برمجة
- تُحفظ بنية النموذج بصيغة `JSON` مرنة تسمح بعدد لا نهائي من النماذج
- **لوحات مؤشرات الأداء**: عدادات ورسوم بيانية تتحدث آلياً
- **التقييم الآلي**: وظيفة دورية تحسب نسبة المنجز من المسند وتحدّث المؤشر
  (٥٠٪ إنجاز + ٣٠٪ حضور + ٢٠٪ تقييم − خصم المهام المتأخرة)
</details>

<details open>
<summary><b>٨. التواصل الفعال والدعم</b></summary>

- **شاشة المحادثات المستقلة**: صندوقٌ واحد يجمع المحادثات الخاصة والمجموعات والمحادثات
  المرتبطة بالعمل. نصوصٌ ومرفقاتٌ و**رسائل صوتية** تُسجَّل من المتصفّح، وردٌّ على رسالةٍ
  بعينها، وتحريرُ الرسالة وحذفُها، وكتمُ الخيط، وعدّادُ ما لم يُقرأ
- **المجموعات**: لها اسمٌ ووصفٌ وصورة عرض يعدّلها مشرفوها، وأدوارٌ داخلها (مشرف/عضو)،
  ومغادرةٌ وإخراج — وكلُّ ذلك يُثبَّت رسائلَ نظاميةً في الخيط
- **الصلاحية المتدرّجة في الإضافة**: مديرُ المجمّع يضمّ الجميع بحكم صلاحيته، ومديرُ الفرع
  كلَّ من يعمل في فروعه ولو كان يعمل في غيرها، ومديرُ اللجنة أعضاءَ لجانه. والدليل لا
  يعرض إلا من يُقبل ضمُّه، والخادم يردّ ما خرج عنه
- **مربع المحادثة السياقي**: يفتح بجانب المهمة أو الفاتورة أو التذكرة — يراه المرتبطون بها فقط
- **مركز التذاكر** برفع التذاكر وتصنيفها ومعالجتها وتغيير حالتها
- **اتصال لحظي** عبر `WebSockets`: الرسائل والإشعارات تظهر فوراً دون تحديث الصفحة
  (خادم `ws` في التشغيل الذاتي، و**Durable Object** على Cloudflare، مع تراجع تلقائي إلى الاستطلاع الدوري)
- **اتفاقيات مستوى الخدمة**: عند تأخر الدعم أكثر من ٢٤ ساعة يُصعّد النظام التذكرة للإدارة ويحوّل لونها للأحمر
</details>

<details open>
<summary><b>٩. التكامل والواجهات البرمجية</b></summary>

- **لوحة إعدادات المطورين** لإصدار وإبطال مفاتيح الربط مع تحديد نطاقات الوصول
- **نقاط اتصال RESTful** لمنصة الطلاب والأنظمة الخارجية (`/api/v1/...`)
- **الحد من الطلبات**: سقف قابل للضبط لكل مفتاح مع رؤوس `X-RateLimit-*` ورمز `429`
</details>

- **استضافة سحابية جاهزة**: نشر بأمر واحد على Cloudflare Workers مع D1 و R2 — أو خادم ذاتي
- **نسخ احتياطي يومي آلي** مضغوط مع سياسة احتفاظ، يُحفظ معزولاً تحت مجلّد الجهة، وقابل للاستعادة مباشرةً

- **مبدّل التقويم** في الشريط العلوي يحوّل كل تواريخ المنصة فوراً
- العربية و`RTL` كخيار افتراضي أساسي لجميع الشاشات
- **توحيد التخزين**: كل الطوابع الزمنية `UTC ISO-8601`
- **التحويل اللحظي**: التحويل إلى هجري (**أم القرى**) أو ميلادي في الواجهة فقط بحسب تفضيل المستخدم

- **تقرير أخطاء مرئي** يحدد رقم الصف والحقل وسبب الرفض

<details open>
<summary><b>١٣. محرك التقارير والطباعة</b></summary>

- **ثلاثة عشر تقريراً** جاهزاً في كتالوجٍ مصنَّفٍ بوحداته وفوقه بحث، مع **لوحة فلاتر متقدمة**
  (التاريخ، الفرع، الفصل، المستخدم، الحالة)
- **إنجاز المهام على أربعة مستويات من تقريرٍ واحد** — المجمّع كلُّه، أو موزَّعاً على الفروع،
  أو على اللجان، أو على المنسوبين. مُبدِّلٌ في اللوحة يعيد التشغيل بمجرّد تبديله، والأعمدةُ
  واحدةٌ في المستويات كلِّها فيُقارَن بينها. ونسبة الإنجاز **موزونةٌ بأوزان المهام** لا بعددها،
  وبجانبها العدديّةُ لمن يريد العدّ المجرّد
- **المهام المتأخرة والمتعثّرة**: أيُّها ومن يتولّاها وكم مضى على استحقاقها — مرتّبةً بالأطول تأخّراً
- **ملخّص الحضور والتأخّر**: سطرٌ لكل منسوب لا لكل يوم، بمجموع دقائق تأخّره ونسبة حضوره
- **الإجازات** و**كشف المنسوبين والعقود** (ومن قارب عقده على الانتهاء) — بلا رواتب، فللراتب تقريرُه المحروس
- تصدير `Excel (.xlsx)` و`CSV` بترميز عربي صحيح
- **مستند PDF رسمي** مُروّس بشعار الجهة واسمها والتاريخ بالتقويمين، بدعم عربي كامل وجداول محافظة على التنسيق
- **استعلامات محسّنة** مخصصة للتقارير الثقيلة — والتجميع يقع في قاعدة البيانات لا في الذاكرة
</details>

<details open>
<summary><b>١٤. سجلات التدقيق والامتثال</b></summary>

- **شاشة سجل النشاطات**: من قام بماذا ومتى، مع عرض الفروق (قبل/بعد)
- **التتبع الآلي** لكل عملية حساسة: إنشاء، تعديل، حذف، اعتماد، رفض، دخول، تصدير
- جدول **`Append-only`** محمي بمُشغّلات قاعدة بيانات تمنع التعديل أو الحذف نهائياً
- امتثال لمبادئ **نظام حماية البيانات الشخصية (PDPL)**: عزل البيانات، تقييد الوصول، تتبع كامل
</details>

## المزايا الإضافية المطلوبة

### 📱 تطبيق مثبّت على الشاشة الرئيسية (PWA)

- **الأندرويد وسطح المكتب**: زر تثبيت مباشر عبر `beforeinstallprompt`
- **الآيفون والآيباد**: دليل تثبيت مصوّر بالخطوات داخل التطبيق (Safari ← مشاركة ← إضافة للشاشة الرئيسية)
- يعمل بملء الشاشة (`standalone`) بأيقونات لكل المقاسات و`maskable` للأندرويد
- **اختصارات سريعة** من الأيقونة: تسجيل الحضور · مهامي · رفع طلب مالي
- **العمل دون اتصال**: عامل خدمة يخزّن هيكل التطبيق وآخر البيانات، مع صفحة بديلة وشريط تنبيه
- **تحديث شامل بلا إعادة تثبيت**: ختم الإصدار (`web/version.js`) يُولَّد عند كل نشر بـ `npm run gen:version`
  ويستورده عامل الخدمة، فيراه المتصفّح إصداراً جديداً ويثبّته منتظراً. تظهر لافتة سفلية «يتوفّر إصدار جديد»،
  وبالضغط على «تحديث الآن» تُمحى كل الذواكر ويُعاد جلب الهيكل من الشبكة ثم يتسلّم العامل الجديد الصفحة
  وتُعاد مرّةً واحدة. والبحث عن الإصدار يتكرّر عند العودة إلى الشاشة وعودة الشبكة وكل ساعة.
  ومن الإعدادات ← التطبيق يظهر الإصدار الحالي وزرّ «التحقق من التحديثات».

### 🔔 نظام الإشعارات المتكامل

ثلاث قنوات تعمل معاً من ناقل واحد (`server/core/notify.js`):

1. **داخل المنصة** — جرس الإشعارات مع عدّاد غير المقروء وصفحة إشعارات كاملة
2. **لحظياً** — `WebSocket` يوصل الإشعار لكل أجهزة المستخدم المفتوحة فوراً (خادم `ws` على Node، و**Durable Object** على Cloudflare، مع تراجع تلقائي إلى الاستطلاع الدوري)
3. **دفع خارجي** — `Web Push (VAPID)` يصل المتصفح والأندرويد وآيفون (iOS 16.4+ بعد التثبيت) حتى والتطبيق مغلق

- **تفضيلات دقيقة**: تحكم بكل قناة وكل فئة (مهام، مالية، حضور، محادثات، تذاكر، نظام)
- إدارة الأجهزة المسجّلة + إشعار تجريبي للتأكد من الوصول
- تنظيف تلقائي للاشتراكات المنتهية (410/404)
- بث إداري عام لكل المنسوبين أو لفرع محدد
- شارة العدد على أيقونة التطبيق (`setAppBadge`)

**الأحداث المُشعِرة**: إسناد مهمة · اقتراب أو تجاوز الاستحقاق · تغيير حالة مهمة · طلب مالي بانتظار اعتمادك ·
اعتماد أو رفض طلبك · رسالة في محادثة سياقية · تذكرة جديدة أو رد عليها · تصعيد SLA · طلب إجازة وقراره ·
صرف الراتب · اكتمال الاستيراد · اكتمال ترحيل الفصل · إعلانات الإدارة.

## البنية التقنية

```
Riyadh-qu/
├─ server/
│  ├─ core/                   النواة المشتركة — تعمل حرفياً على البيئتين
│  │  ├─ schema.sql           المخطط (٦٢ جدولاً + ٤٥ فهرساً + ١٣ مُشغّل حماية)
│  │  ├─ sql.js               عقد قاعدة البيانات غير المتزامن (get/all/run/batch/exec)
│  │  ├─ crypto.js            JWT · PBKDF2 · HKDF بواجهة Web Crypto القياسية
│  │  ├─ webpush.js           RFC 8291 + RFC 8292 مكتوبتان بلا اعتماديات
│  │  ├─ workhours.js         جداول الدوام: المجمّع ← الفرع ← الموظف، والتأخّر وأيام العمل
│  │  ├─ routes/              ١٧ وحدة تغطي بنود الوثيقة وطبقة الـ SaaS
│  │  ├─ billing.js           الاشتراكات والحدود والفواتير والضريبة
│  │  ├─ provision.js         تجهيز جهة جديدة ومحوها
│  │  ├─ jobs/                الترحيل · الاستيراد · المؤشرات · SLA · النسخ الاحتياطي
│  │  ├─ middleware/          المصادقة · RBAC · التدقيق · الحد من الطلبات
│  │  └─ …                    العزل · الإشعارات · التخزين · التقارير · Excel/ZIP · أم القرى
│  ├─ node/                   محوّل التشغيل الذاتي : better-sqlite3 · القرص · ws
│  └─ worker/                 محوّل Cloudflare      : D1 · R2 · Durable Object · Assets
├─ web/                       الواجهة (SPA بوحدات ES دون خطوة بناء)
│  ├─ js/views/               ٢٢ شاشة (منها المحادثات وأوقات الدوام والاشتراك ولوحة المالك)
│  ├─ js/icons.js             أيقونات لوسايد — المصدر الوحيد للأيقونات في المنصة
│  ├─ css/app.css             نظام التصميم — توكنز هوية «سنا» في كتلة `:root` وحدها
│  ├─ assets/brand/           الشعار والمونوغرام والنمط الزخرفي (النجمة الثمانية)
│  ├─ sw.js                   عامل الخدمة (تخزين + إشعارات الدفع)
│  ├─ _headers                رؤوس الأمان على شبكة Cloudflare (مولَّد)
│  └─ manifest.webmanifest    بيان التطبيق
├─ migrations/                ترحيل D1 (مولَّد من schema.sql)
├─ wrangler.toml              ربط Workers · D1 · R2 · Durable Objects · Cron
└─ scripts/                   التدقيق · فحص الهوية · VAPID · الأيقونات · النسخ · أدوات Cloudflare
```

**شيفرة واحدة، محوّلان.** كل المنطق في `server/core` ولا يعرف بيئته: قاعدة البيانات خلف واجهة
غير متزامنة موحّدة، والتعمية والدفع والضغط والتقويم مبنية على واجهات الويب القياسية المتاحة في
Node وفي Workers معاً. المحوّلان لا يزيدان عن ربط المزوّدات.

**لماذا بلا خطوة بناء؟** الوثيقة تشترط فصل الواجهة عن الخادم — وهو محقق بالكامل (SPA مستقلة + REST).
اعتماد وحدات ES الأصلية يلغي مخاطر أدوات البناء ويجعل النشر نسخ ملفات فقط، مع بقاء الواجهة
قابلة للاستبدال بـ React أو Vue لاحقاً دون أي تغيير في الخادم.

**قاعدة البيانات**: SQLite في التشغيل الذاتي و**Cloudflare D1** في السحابة — بالمخطط نفسه
والمُشغّلات نفسها، والمصدر الوحيد هو `server/core/schema.sql`.

## الهوية البصرية

المنصة مبنية على **دليل الهوية البصرية — رقيم، الإصدار ١٫٠ (هوية «سنا»)**، وهو ملزمٌ
لكل شاشة أو مكوّن أو نصّ واجهة جديد. المرجع الكامل: **[docs/IDENTITY.md](docs/IDENTITY.md)**.

| المحور | الضابط |
|---|---|
| الألوان | أخضر سنا `#2F8A6F` أساساً · قشدي `#FBF7EF` خلفيةً · مشمشي `#E8A25C` تمييزاً بما لا يتجاوز ٧٪ من أي شاشة |
| المصدر | توكنز `:root` في `web/css/app.css` وحدها — لا قيمة لون مباشرة في أي مكوّن |
| الخطوط | Zain للعناوين · IBM Plex Sans Arabic للنصوص — لا خط ثالث |
| الأيقونات | Lucide حصراً عبر `web/js/icons.js` — لا رموز تعبيرية |
| الاتجاه | RTL بالكامل بخصائص منطقية فقط (`inset-inline-*` لا `left/right`) |
| الشعار والنمط | `web/assets/brand/` تُستعمل كما هي ولا يُعاد رسمها |
| الزجاج فوق النمط | النمط مضبَّب (`pattern-soft-*.svg` من `npm run gen:pattern`) وتحته غشاء: `--glass-on-brand` / `--glass-on-ink` / `--glass-on-light` — فيبقى ظاهراً جزئياً بلا مزاحمة النص |

والالتزام مفحوصٌ آلياً:

```bash
npm run verify:identity
```

يمسك الفحص خمسة أنواع من الانحراف: ألوان مباشرة خارج التوكنز، ورموز تعبيرية في
الواجهة، وخصائص اتجاه فيزيائية، وأسماء أيقونات غير معرّفة، وخطوطاً خارج الهوية.

| `npm run verify:wiring` | ٥٠ فحص توصيل بين الخادم والواجهة (بلا خادم) |
| `npm run verify:realtime` | القناة اللحظية والوظائف المجدولة |
| `npm run verify:identity` | الانحراف عن دليل الهوية البصرية (بلا خادم) |
| `npm run verify:all` | الأربعة معاً |

> جميع أوامر التدقيق تقبل `BASE` لاستهداف أي بيئة:
> `BASE=http://localhost:8787 npm run verify:all`

## الإعدادات

في التشغيل الذاتي: انسخ `.env.example` إلى `.env`.
على Cloudflare: `[vars]` في `wrangler.toml` للعلني، و`wrangler secret put` للسرّي.

| المتغير | الوصف |
|---|---|
| `JWT_SECRET` | **غيّره في الإنتاج** — مفتاح توقيع الجلسات |
| `DB_FILE` | مسار قاعدة البيانات (التشغيل الذاتي فقط) |
| `VAPID_*` | مفاتيح إشعارات الدفع (`npm run gen:vapid` أو `npm run cf:secrets`) |
| `BACKUP_ENABLED` / `BACKUP_KEEP` | النسخ الاحتياطي اليومي وعدد النسخ المحفوظة |
| `GEOFENCE_DEFAULT_RADIUS` | نطاق التحضير الافتراضي بالمتر |
| `GOOGLE_MAPS_API_KEY` | مفتاح **Map Tiles API** لخرائط قوقل — وحده يفتح القمر الصناعي والتضاريس. مئة ألف مربّعٍ شهرياً بلا مقابل، لكنّه يشترط بطاقةً وفوترةً مفعّلة |
| `GEOAPIFY_API_KEY` | مفتاح **Geoapify** — بديلٌ مجاني بلا بطاقة. والمفتاحان الأيسر ضبطهما من لوحة المنصة ← الإعدادات ← الخرائط بلا إعادة نشر، وبلا أيّهما تعمل الطبقة المفتوحة |
| `RATE_LIMIT_*` · `LOGIN_ACCOUNT_MAX` | حدود الطلبات ومحاولات الدخول |
| `BOOTSTRAP_TOKEN` | يحمي مسار التهيئة على Cloudflare |

## النشر

### على Cloudflare (موصى به)

كل المزوّدات من كلاود فلير: Workers للاستضافة، D1 لقاعدة البيانات، R2 للملفات،
Durable Objects للبثّ اللحظي، Cron Triggers للوظائف المجدولة.
الخطوات بالتفصيل في **[docs/CLOUDFLARE.md](docs/CLOUDFLARE.md)**.

### على خادم ذاتي

1. `NODE_ENV=production` مع `JWT_SECRET` قوي وعشوائي
2. تشغيل خلف عاكس (Nginx/Caddy) بشهادة **HTTPS** — إلزامية لعمل عامل الخدمة وإشعارات الدفع وخدمة الموقع
3. تمرير ترقية `WebSocket` على المسار `/ws`
4. تفعيل النسخ الاحتياطي اليومي والاحتفاظ بنسخ خارج الخادم

## التدقيق والاختبارات

```bash
npm run setup            # نسخة نظيفة أولاً — التدقيق يفترض بيانات ابتدائية
npm run verify:wiring    # ٩٣ فحص توصيل: كل قدرة لها مسار خادم *وواجهة* تستدعيه
npm run verify           # ٩٧٤ فحصاً وظيفياً في ٢٦ قسماً
npm run verify:realtime  # ٩ فحوص للقناة اللحظية (+٧ للوظائف المجدولة على Cloudflare)
```

> `verify:wiring` يقرأ المصدر بلا خادم، ويكشف ما لا يكشفه فحص الواجهة البرمجية:
> مساراً بُني ولم تُبنَ له شاشة — فتمرّ الفحوص كلها بينما القدرة غير متاحة للمستخدم.

> التدقيق يستهلك حصص الطلبات عمداً (يختبر حدّ المفتاح العام وسقف التسجيل بالساعة)، فتشغيله
> مرّتين متتاليتين على النسخة نفسها يتوقّف برسالة صريحة تشرح السبب بدل أن يتهاوى بأخطاء مضلّلة.
> أعِد التهيئة بين التشغيلين، أو ارفع الحد مؤقتاً: `RATE_LIMIT_MAX=5000 npm start`.

التدقيق لا يكتفي برموز الاستجابة، بل يتحقق من الحسابات والقيود فعلياً: مسافة هافرساين ورفض
التحضير خارج النطاق، حساب الخصومات والراتب الصافي من جدول دوام كلِّ موظف، منع تخطّي خطوات الاعتماد المالي، رفض
الكتابة على فصل مؤرشف، عزل بيانات الفروع، استحالة تعديل سجل التدقيق، صحة تحويل أم القرى،
تقارير الأخطاء المرئية في الاستيراد، وأصول تطبيق PWA. ويغطي القسم التاسع عشر طبقة الـ SaaS
كاملةً: التسجيل الآلي وعزل الجهة الجديدة، تطبيق حدود الخطة، حساب الضريبة،
دورة التجربة والفاتورة والمهلة وتوقّف الكتابة ثم عودتها بالسداد، الإيقاف الإداري وبقاء القراءة،
الدخول الإداري وتسجيله في السجلَّين، ومحو الجهة مع بقاء أثره.
ويغطي القسمان الخامس والعشرون والسادس والعشرون: وراثة جداول الدوام على طبقاتها الثلاث
وأثرها في التأخّر والمسير، والمحادثات المستقلة بصلاحيتها المتدرّجة في الإضافة.

ويغطي القسم العشرون المستويات الأربعة: حجب الوحدات غير المشمولة بالخطة، سلسلة المؤشرات
ومعدل التسرّب، سجل تشغيل الوظائف، التناسب المبني على المدفوع فعلاً لا على سعر القائمة،
تقييم صحة الجهات، البثّ الموجّه ووصوله، دورة الدعم المُصعَّد، ختم ZATCA وفكّ رمز QR وسلامة
سلسلة التجزئة، التحقّق بخطوتين ورموز الاسترداد وعدم إعادة استخدامها، تقرير محاولات الدخول،
تصدير جهة **دون تسريب** بيانات جهة أخرى ولا إعدادات المنصة، الكوبونات وسريانها على التجديدات،
الإشعارات الدائنة على المسدَّد وغير المسدَّد، عدم تسريب مفاتيح بوابة الدفع، وتجاوزات الحدود
والمزايا لكل جهة.

**نتيجة التدقيق على البيئتين:**

| البيئة | الفحوص الوظيفية | القناة اللحظية |
|---|---|---|
| التشغيل الذاتي (Node + SQLite) | ٦١٨ / ٦١٨ ✔ | ٩ / ٩ ✔ |
| Cloudflare (Workers + D1 + R2 + DO) | ٦١٨ / ٦١٨ ✔ | ١٦ / ١٦ ✔ |

وفوقها فحوص متصفّح آلية تعمل على البيئتين بصفر أخطاء في وحدة التحكم:
شاشات لوحة إدارة المنصة الخمس عشرة · لوحة المنصة على الجوال · كتابة فعلية من الواجهة
(كوبون وإعلان وإشعار دائن) ·
**تدقيق جوال** على مقاس iPhone يرفض أي تمرير أفقي أو هدف لمس دون ٢٨px ·
**تدقيق التطبيق المثبَّت** (وضع standalone، وصول الإشعارات، والعمل دون اتصال على كل المسارات).

كما جرى اختبار الواجهة آلياً على متصفح حقيقي (Chromium) في وضعي سطح المكتب والجوال (iPhone)
على البيئتين: تحميل كل الشاشات، تسجيل الدخول، النسخ الاحتياطي، **شاشات لوحة إدارة المنصة
الخمس عشرة كلها**، إنشاء كوبون وبثّ إعلان وحذفه من الواجهة نفسها، شاشة الاشتراك،
صفحتا الأسعار والتسجيل العامّتان، القناة اللحظية، وخلوّ عرض الجوال من التمرير الأفقي —
دون أي خطأ في وحدة التحكم.
